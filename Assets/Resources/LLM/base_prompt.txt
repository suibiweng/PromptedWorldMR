### RUNTIME API (Unity Lua Proxies) — READ BEFORE CODING

HARD RULES
- Do NOT call GetComponent / AddComponent / GetComponentInChildren / GetComponentInParent from Lua.
- Do NOT assign C# fields/properties on userdata directly (e.g., `rigidbody.useGravity = true` is INVALID).
- Use only the proxies and methods listed below.
- Transform uses PROPERTIES (set with `=`), not "SetXxx" methods.

Valid examples:
  self.transform.name = "MyObject"
  self.transform.localScale = { x=1, y=1, z=1 }
  self.rigidbody:SetUseGravity(true)
Invalid examples:
  self.transform:SetName("MyObject")
  self.transform:SetLocalScale({x=...,y=...,z=...})
  self.transform:SetColor({...})
  self.rigidbody.useGravity = true

GENERAL
- self.gameObject and self.transform are always available.
- Accessing self.rigidbody / self.audio (audioSource) / self.particles (particleSystem) lazily binds a proxy.
  If missing, the runtime may auto-add a safe default (Rigidbody is kinematic + no gravity by default).


VECTORS
- Getters like `transform.position` return a Vector3Proxy with fields `x, y, z` (writes write back).
- Setters accept `{ x=..., y=..., z=... }`.

EVENTS TO IMPLEMENT (optional)
- start(self), update(self, dt), on_trigger(self, other), on_collision(self, col), on_stop(self)

----------------------------------------------------------------
COMPOUND COLLIDERS & PARENT NAMES (IMPORTANT)
----------------------------------------------------------------
- LuaBehaviour + Rigidbody live on the PARENT object you are scripting.
- Child colliders (no Rigidbody) are treated as a compound collider of that parent.
- Unity routes collisions from child colliders to the parent Rigidbody + LuaBehaviour.
- In on_collision(self, col):
  - self.transform.name is THIS object's name (your programmed object).
  - col:GetRootName() gives the OTHER object's top-level parent name.

Recommended pattern for prompts like "if this ball hits the desk then turn red":

```lua
function on_collision(self, col)
  local my_name = self.transform.name
  local other_root = col:GetRootName()

  if other_root == "DESK" then
    if self.particles then
      self.particles:Play()
    end
  end

### ANIMATION / DOTWEEN POLICY (MANDATORY)
- Do NOT create any animation, tween, or time-based transform changes UNLESS the user explicitly asks for movement, animation, or effects.
- If the user does NOT mention animation, movement, tweening, bouncing, pulsing, shaking, or similar behavior, then:
  - Do NOT call DOTween / dotween functions.
  - Do NOT gradually change transform.position / localPosition / localScale / eulerAngles over time for visual flair.
- Only add DOTween calls (MoveTo, ScaleTo, etc.) when the prompt clearly requests an animation or movement.
- Physics (gravity, AddForce, collisions) is allowed when requested; but do not add extra decorative animations without explicit instruction.


### PHYSICS POLICY (MANDATORY)
- The engine automatically turns OFF isKinematic when you:
  - Enable gravity (SetUseGravity(true))
  - Apply forces or impulses (AddForce / AddImpulse)
  - Set velocity (SetVelocity)
- Therefore, in NORMAL USE you MUST NOT call:
  - self.rigidbody:SetIsKinematic(...)
  - self.rigidbody:SetKinematic(...)
- Only touch kinematic if the USER EXPLICITLY MENTIONS:
  - "kinematic", "freeze in place", "disable physics", or similar.
- When the user just asks for gravity, force, bouncing, or physics behavior:
  - Use SetUseGravity / AddForce / AddImpulse / SetVelocity
  - DO NOT add extra SetIsKinematic / SetKinematic calls.
