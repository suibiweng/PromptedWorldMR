### RUNTIME API (Unity Lua Proxies) — READ BEFORE CODING

HARD RULES
- Do NOT call GetComponent / AddComponent / GetComponentInChildren / GetComponentInParent from Lua.
- Do NOT assign C# fields/properties on userdata directly (e.g., `rigidbody.useGravity = true` is INVALID).
- Use only the proxies and methods listed below.
- Transform uses PROPERTIES (set with `=`), not "SetXxx" methods.

Valid examples:
  self.transform.name = "MyObject"
  self.transform.localScale = { x=1, y=1, z=1 }
  self.rigidbody:SetUseGravity(true)

Invalid examples:
  self.transform:SetName("MyObject")
  self.transform:SetLocalScale({x=...,y=...,z=...})
  self.transform:SetColor({...})
  self.rigidbody.useGravity = true

------------------------------------------------------------
GENERAL
------------------------------------------------------------
- self.gameObject and self.transform are always available.
- Accessing self.rigidbody / self.audio / self.particles lazily binds a proxy.
- If missing, the runtime may auto-add a safe default (Rigidbody is kinematic + no gravity).

------------------------------------------------------------
VECTORS
------------------------------------------------------------
- Getters like transform.position return a Vector3Proxy with fields x,y,z.
- Writes write back automatically.
- Setters accept tables: { x=..., y=..., z=... }

------------------------------------------------------------
IOT PROXY (global: iot)
------------------------------------------------------------

Used for simulated IoT control in VR.

Methods:
- iot:On(deviceId)
- iot:Off(deviceId)
- iot:Send(deviceId,"ON"/"OFF")

Rules:
- Only use device IDs provided in the prompt.
- NEVER invent device IDs.
- IoT affects logical state only.
- Prefer calling IoT in on_trigger or on_collision.
- Do NOT call IoT every frame.

Before using IoT:
1. Check user intent involves device control.
2. Check a matching device exists.
3. Only then call IoT.

------------------------------------------------------------
COLLISION SYSTEM (IMPORTANT)
------------------------------------------------------------

- LuaBehaviour lives on the parent.
- Collisions may come from TWO systems:
  1) Unity physics collisions (Colliders/Rigidbody)
  2) Custom bounds collisions (CollisionManager + SimpleCollidable)

Both systems route collision events to the parent LuaBehaviour, and Lua always receives:
function on_collision(self, col)

In on_collision:
- self.transform.name = THIS object
- col:GetRootName() = OTHER object (root name)

Objects may have runtime suffixes:
OBJECT, OBJECT_1, OBJECT_2, etc.

NEVER rely on exact equality.

Use prefix matching:

string.match(other_root,"^OBJECT")


------------------------------------------------------------
ANIMATION / DOTWEEN POLICY
------------------------------------------------------------

Do NOT create animations unless user explicitly asks.

If user does NOT mention animation:
- No DOTween
- No time-based transform changes

Only use DOTween when explicitly requested.

------------------------------------------------------------
PHYSICS POLICY
------------------------------------------------------------

Engine auto-disables kinematic when:
- gravity enabled
- forces applied
- velocity set

Therefore:
- DO NOT call SetIsKinematic unless user explicitly asks.

For physics:
- Use SetUseGravity / AddForce / AddImpulse / SetVelocity


----------------------------------------------------------------
DOTWEEN (global: dotween)
----------------------------------------------------------------

Use DOTween ONLY when the user explicitly asks for animation,
movement, breathing, pulsing, bouncing, fading, or visual effects.

Do NOT use dotween for normal logic or physics.

All functions return a HANDLE (number) which can be reused.

------------------------
BASIC TWEENS
------------------------

Move:
- dotween:MoveTo(transform, x, y, z, duration, ease?)
- dotween:MoveTo(transform, x, y, duration, ease?) 
  (keeps current Z)

Rotate:
- dotween:RotateTo(transform, x, y, z, duration, ease?)
- dotween:RotateYTo(transform, y, duration, ease?)
- dotween:RotateXTo(transform, x, duration, ease?)
- dotween:RotateZTo(transform, z, duration, ease?)

Scale:
- dotween:ScaleTo(transform, x, y, z, duration, ease?)
- dotween:ScaleTo(transform, x, y, duration, ease?) 
  (keeps current Z)

Canvas fade:
- dotween:CanvasFade(gameObject, alpha, duration, ease?)

Ease examples:
"Linear"
"OutQuad"
"InOutSine"
"InOutQuad"
"OutBack"

------------------------
TWEEN CONTROL
------------------------

Given a handle:
- dotween:Pause(handle)
- dotween:Play(handle)
- dotween:Kill(handle)
- dotween:SetLoops(handle, loops, loopType?)
    loopType: "restart", "yoyo", "incremental"

Example breathing loop:
local h = dotween:ScaleTo(self.transform, 1.1,1.1,1.1,1.2,"InOutSine")
dotween:SetLoops(h, -1, "yoyo")

------------------------
SEQUENCES
------------------------

Create:
local seq = dotween:SeqCreate()

Append:
- dotween:SeqAppendMove(seq, transform, x,y,z,duration,ease?)

Join:
- dotween:SeqJoinScale(seq, transform, x,y,z,duration,ease?)

Interval:
- dotween:SeqAppendInterval(seq, seconds)

Control:
- dotween:SeqPlay(seq)
- dotween:SeqKill(seq)
- dotween:SeqSetLoops(seq, loops, loopType?)



----------------------------------------------------------------
PokeButtonProxy (self.button)
----------------------------------------------------------------
Use this proxy to read button/poke interaction state from Lua.
This represents a VR poke/press button.

Available when the GameObject has a PokeButton component.

STATE READ (from Lua):

- self.button:IsPressed() -> bool
    True while finger is pressing the button.

- self.button:WasPressed() -> bool
    True only on the frame the press begins.

- self.button:WasReleased() -> bool
    True only on the frame the press ends.

- self.button:WasClicked() -> bool
    True when a valid click occurs (respecting debounce and minPressTime).

TOGGLE MODE:

- self.button:GetToggleState() -> bool
    Returns current toggle state (true = ON, false = OFF).

- self.button:SetToggleMode(bool)
    Enables or disables toggle mode.
    When enabled, each click flips the toggle state.

USAGE PATTERNS:

Example — toggle a lamp on each press:

function update(self, dt)
    if self.button and self.button:WasClicked() then
        if self.button:GetToggleState() then
            iot:On("LAMP01")
        else
            iot:Off("LAMP01")
        end
    end
end

Example — hold to keep device on:

function update(self, dt)
    if self.button and self.button:IsPressed() then
        iot:On("LAMP01")
    else
        iot:Off("LAMP01")
    end
end

NOTES:
- Prefer checking button state in update(self, dt).
- Do NOT spam IoT every frame unless needed.
- Button proxy is read-only for interaction state.

- Do NOT create tweens every frame in update().
- Infinite loops must use SetLoops(-1,"yoyo") instead of manual logic.
