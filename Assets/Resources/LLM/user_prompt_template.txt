IOT
--------------------------------------------------
- You may use iot:On(id) or iot:Off(id)
- You may use iot:Send(id, command) for supported non-ON/OFF commands
- For light bulb RGB, prefer the special cached API when multiple scripts or multiple objects control separate RGB channels:
  local bulb = iot:LightBulb("BULB01")
  bulb:SetRGB(r, g, b)
  bulb:SetRed(r)
  bulb:SetGreen(g)
  bulb:SetBlue(b)
- The special light bulb API stores the other RGB channels globally in IOTManager and sends one full RGB URL, so separate scripts can safely control red/green/blue without overwriting each other.
- You may also call iot:SetRGB("BULB01", r, g, b), iot:SetRed("BULB01", r), iot:SetGreen("BULB01", g), or iot:SetBlue("BULB01", b).
- Only use IDs from AVAILABLE_IOT_DEVICES
- Only use commands supported by that device
- For TV devices, possible listed commands may include NEXT, PREVIOUS, VOLUME:0.5, CHANNEL:1
- For speaker devices, possible listed commands may include NEXT and VOLUME:0.5
- For light bulb devices, possible listed commands may include TOGGLE, RGB:255:0:0, HSV:120:100:100, BRIGHTNESS:75, TEMPERATURE:3500, STATE, DISCOVER
- If the prompt says room/environment color, or "make this room blue/red/green/etc.", choose a listed device that supports RGB or HSV and send a color command. Do not choose an ON/OFF-only lamp/plug for color.
- If the prompt says room/environment darker/brighter/dim/bright, choose a listed device that supports BRIGHTNESS and send a brightness command. Do not choose an ON/OFF-only lamp/plug for brightness.
- If multiple lights exist, prefer the device whose type/display name/ID says bulb/color/RGB for color or brightness, and prefer lamp/plug only for plain on/off requests.
- Only use IoT if user intent clearly involves real-world device control
- If no relevant device exists, do not use iot
- Never send IoT commands continuously every frame
- For analog controls like volume, rate-limit by value change; do not send every frame if the mapped value has barely changed
- For button holds, call IoT only on press/release transitions
- For collisions, call IoT only on collision entry unless repeated behavior is explicitly requested

--------------------------------------------------
PROXY USAGE
--------------------------------------------------
- Only use provided proxies (transform, rigidbody, particles, etc.)
- NEVER call Unity APIs like GetComponent, AddComponent, etc.
- Use proxy properties, not SetX methods
- Use scene:FindObject("ObjectName") or world:FindObject("ObjectName") to control another selected/registered object from this script.
- scene:FindObject returns a GameObjectProxy. Use GetTransformProxy(), GetRigidbodyProxy(), SetColor(), SetColorHex(), SetActive(), or GetProgramableObjectProxy().
- Always nil-check scene lookup results before using them.

Transform example:
local p = self.transform.position
p.y = p.y + 1
self.transform.position = {x=p.x,y=p.y,z=p.z}

Cross-object physics example:
local target = scene:FindObject("Sphere_1")
if target then
    local rb = target:GetRigidbodyProxy()
    if rb then
        rb:SetIsKinematic(false)
        rb:SetUseGravity(true)
    end
end

- If the user says close/near/approach a named scene object and not "this object", use scene lookup and manual distance:
  local target = scene:FindRealObject("Table") or scene:FindObject("Table")
  local head = user and user:GetHeadPosition()
  local t = target and target:GetTransformProxy()
  local p = t and t.position
  local close = false
  if head and p then
      local dx = head.x - p.x
      local dy = head.y - p.y
      local dz = head.z - p.z
      close = math.sqrt(dx*dx + dy*dy + dz*dz) <= 1.0
  end

OBJECT SIZE / OBJECT DISTANCE CONTROL
--------------------------------------------------
- For object-to-object distance, use scene lookup for both objects, TransformProxy.position, and manual dx/dy/dz distance math.
- For object size, use TransformProxy.localScale. Use average scale such as (s.x + s.y + s.z) / 3 when the prompt says general size.
- For real furniture/physical anchors use scene:FindRealObject(name); for spawned/generated objects use scene:FindVirtualObject(name); if unsure use scene:FindObject(name).
- For continuous color, map a 0..1 value to RGB and call SetColor or SetColorHex only when needed.
- For continuous speaker/TV volume, map to 0..1 and send iot:Send(id, "VOLUME:" .. tostring(value)) only when the value changes meaningfully.
- For continuous light bulb color, map values to 0..255 and prefer iot:LightBulb(id):SetRGB(r,g,b) or SetRed/SetGreen/SetBlue when individual objects control individual channels. Only send when color changes meaningfully.
- For continuous light bulb brightness, map values to 0..100 and send iot:Send(id, "BRIGHTNESS:" .. tostring(value)) only when brightness changes meaningfully.
- For threshold light behavior, track self.wasAboveThreshold or self.lightOn so iot:On/Off fires only when crossing the threshold.
- Keep on_collision empty unless the user explicitly says hit/collide.

Object distance example:
local a = scene:FindRealObject("Desk") or scene:FindObject("Desk")
local b = scene:FindVirtualObject("Sphere") or scene:FindObject("Sphere")
local at = a and a:GetTransformProxy()
local bt = b and b:GetTransformProxy()
local ap = at and at.position
local bp = bt and bt.position
if ap and bp then
    local dx = ap.x - bp.x
    local dy = ap.y - bp.y
    local dz = ap.z - bp.z
    local distance = math.sqrt(dx*dx + dy*dy + dz*dz)
    local value = math.max(0, math.min(1, 1 - ((distance - 0.2) / 2.0)))
end

--------------------------------------------------
COLLISION
--------------------------------------------------
- self is always the parent object
- Collisions may come from TWO systems:
  1) Unity physics collisions
  2) Custom bounds collisions (CollisionManager + SimpleCollidable)
- Lua always receives: on_collision(self, col)
- Prefer col:Matches("name or label") for collision target checks
- Runtime GameObject names may be generic, such as ProgramableObject_Virtual
- Never use ProgramableObject_Virtual, ProgramableObject_Real, or ProgramableObject_* as a col:Matches target
- Never use long internal generated object IDs as col:Matches targets; use human terms like Sphere, Cube, or the visible label
- If the user says anything, something, any object, or does not name the collided object, do not call col:Matches; run the collision action unconditionally
- col:Matches checks the other object's IoT DeviceId, IoT display name, object ID, display label, runtime name, and root name
- For IoT objects, prefer matching by IoT display name or DeviceId
- Use col:GetDisplayLabel(), col:GetObjectId(), or col:GetIdentityText() for debugging/inspection
- NEVER rely on exact equality
- Use prefix/pattern matching only if col:Matches is not enough
- Do NOT rely on contact-point / normal / relative-velocity data
  (bounds collisions do not provide real contact information)

Example:
if col:Matches("Desk") then
    if self.particles then self.particles:Play() end
end

Example for "hits something" or "collides with anything":
function on_collision(self, col)
    iot:Off("LAMP01")
